# 20260506 [FULL] 카메라 연결 끊김 표시 계획

## 1. 목표

라즈베리 파이 또는 라즈베리 파이 카메라와 대시보드 연결이 끊겼을 때, 대시보드의 `실시간 카메라` 영역에 연결 끊김 상태를 명확히 표시한다.

현재 대시보드는 `/video_feed` MJPEG 이미지를 표시하고 있으며, 이미지 로딩 오류 발생 시에만 `handleCameraError()`가 실행된다. 하지만 실제 운영에서는 서버와 브라우저의 MJPEG 연결은 유지된 채 마지막 프레임만 멈출 수 있으므로, `img.onerror`만으로는 연결 끊김을 안정적으로 감지하기 어렵다.

따라서 서버가 최근 프레임 수신 시각과 라즈베리 파이 상태 갱신 시각을 기준으로 연결 상태를 계산하고, 대시보드가 이를 주기적으로 조회해 화면에 반영하도록 한다.

## 2. 현재 구조

### 2.1. 영상 경로

```text
Raspberry Pi
  -> POST /stream/h264 또는 POST /frame
  -> server/app.py
  -> current_frame 갱신
  -> GET /video_feed
  -> dashboard img#camera-stream
```

### 2.2. 상태 경로

```text
Raspberry Pi
  -> POST /status 또는 WebSocket /ws/robot/{robot_id}
  -> server/app.py robot_status 갱신
  -> GET /get_status
  -> dashboard system status bar
```

### 2.3. 관련 파일

- `server/app.py`
  - `/frame`
  - `/stream/h264`
  - `/video_feed`
  - `/api/stream_status`
  - `/status`, `/get_status`
  - `/ws/robot/{robot_id}`
- `frontend/templates/index.html`
  - `#camera-stream`
  - `#no-camera-msg`
- `frontend/static/script.js`
  - `handleCameraError()`
  - `/get_status` polling
- `frontend/static/style.css`
  - `.no-camera-bg`
- `raspberry/pi_client.py`
  - JPEG frame upload
  - status upload
  - command WebSocket

## 3. 문제 정의

### 3.1. `img.onerror`만으로 부족한 이유

`/video_feed` 응답이 열린 상태에서 새 프레임만 들어오지 않는 경우가 있다.

이때 브라우저 입장에서는 이미지 요청 자체가 즉시 실패하지 않으므로 `onerror`가 호출되지 않을 수 있다. 결과적으로 대시보드는 마지막 프레임을 계속 보여주거나, 사용자가 보기에는 멈춘 화면인데도 `연결된 카메라가 없습니다` 메시지가 표시되지 않을 수 있다.

### 3.2. 구분해야 하는 상태

1. 서버는 살아 있지만 아직 프레임이 없음
2. 라즈베리 파이는 상태를 보내고 있지만 카메라 프레임만 안 들어옴
3. 라즈베리 파이 자체가 서버와 끊김
4. H.264 디코딩 또는 ffmpeg 오류 발생
5. 정상적으로 프레임 수신 중

## 4. 설계 방향

서버에서 카메라 상태를 하나의 값으로 계산하고, 프론트는 이 값을 기준으로 UI만 갱신한다.

권장 상태값:

```text
live
waiting
camera_disconnected
robot_disconnected
error
```

각 상태의 의미:

| 상태 | 의미 | 대시보드 표시 |
| --- | --- | --- |
| `live` | 최근 프레임 정상 수신 | 영상 표시 |
| `waiting` | 서버 시작 후 아직 프레임 없음 | 회색 화면 + 카메라 신호 대기 중 |
| `camera_disconnected` | 라즈베리 파이 상태는 살아 있으나 프레임이 일정 시간 없음 | 회색 화면 + 카메라 연결이 끊겼습니다 |
| `robot_disconnected` | 상태 갱신과 프레임 수신이 모두 일정 시간 없음 | 회색 화면 + 라즈베리 파이와 연결이 끊겼습니다 |
| `error` | 디코딩, ffmpeg, 프레임 처리 오류 | 회색 화면 + 카메라 스트림 오류 |

## 5. 서버 변경 계획

대상 파일: `server/app.py`

### 5.1. 타임아웃 설정 추가

환경 변수로 조정 가능하게 둔다.

```python
CAMERA_TIMEOUT_SEC = float(os.getenv("CAMERA_TIMEOUT_SEC", "3.0"))
ROBOT_STATUS_TIMEOUT_SEC = float(os.getenv("ROBOT_STATUS_TIMEOUT_SEC", "5.0"))
```

기본값:

- 카메라 프레임 타임아웃: 3초
- 라즈베리 파이 상태 타임아웃: 5초

### 5.2. 공통 프레임 수신 시각 갱신

`process_and_publish_frame()`에서 H.264와 JPEG 방식 모두 공통으로 최신 프레임 시각을 갱신한다.

추가 또는 보강할 값:

```python
stream_stats["connected"] = True
stream_stats["robot_id"] = robot_id
stream_stats["last_frame_at"] = time.time()
stream_stats["last_error"] = None
```

현재 H.264 디코딩 루프에서는 `last_frame_at`이 갱신되지만, `/frame` JPEG 업로드 경로도 동일하게 상태 계산에 포함되도록 한다.

### 5.3. 연결 상태 계산 함수 추가

예상 함수:

```python
def build_camera_status(now=None):
    ...
```

계산에 사용할 값:

- `current_frame is not None`
- `stream_stats["last_frame_at"]`
- `stream_stats["connected"]`
- `stream_stats["last_error"]`
- `robot_status["updated_at"]`
- WebSocket 연결 여부는 비동기이므로 필요 시 API 레벨에서 보조로 합성

판정 우선순위:

1. `last_error`가 있고 최근 프레임이 없으면 `error`
2. 최근 프레임이 `CAMERA_TIMEOUT_SEC` 이내면 `live`
3. 서버 시작 후 프레임을 한 번도 받은 적 없으면 `waiting`
4. 최근 상태 갱신도 `ROBOT_STATUS_TIMEOUT_SEC` 이상 없으면 `robot_disconnected`
5. 상태 갱신은 살아 있으나 프레임만 없으면 `camera_disconnected`

### 5.4. `/api/stream_status` 응답 확장

기존 디버그 필드는 유지하고, 대시보드용 필드를 추가한다.

예상 응답:

```json
{
  "camera_state": "camera_disconnected",
  "camera_connected": false,
  "message": "카메라 연결이 끊겼습니다",
  "last_frame_age_sec": 4.2,
  "last_status_age_sec": 1.1,
  "has_current_frame": true,
  "received_fps": 0,
  "last_error": null
}
```

호환성을 위해 기존 필드는 삭제하지 않는다.

### 5.5. 스트림 종료 시 처리 보강

`/stream/h264` 요청이 종료되면 현재처럼 `stream_stats["connected"] = False`를 유지한다.

단, 마지막 프레임은 즉시 지우지 않는다. 대신 프론트가 상태 API를 보고 오버레이를 표시한다. 이렇게 하면 일시적인 끊김에도 화면이 급격히 검은 화면으로 바뀌지 않고, 사용자는 마지막 화면 위에서 연결 끊김 메시지를 볼 수 있다.

## 6. 프론트엔드 변경 계획

대상 파일:

- `frontend/templates/index.html`
- `frontend/static/script.js`
- `frontend/static/style.css`

### 6.1. 기존 메시지 영역 재사용

현재 HTML:

```html
<div id="no-camera-msg" class="no-camera-bg" style="display: none;">연결된 카메라가 없습니다</div>
<img id="camera-stream" src="{{ url_for('video_feed') }}" alt="" onerror="handleCameraError()">
```

`#no-camera-msg`를 동적 상태 메시지 영역으로 재사용한다.

표시 문구 예시:

- `카메라 신호 대기 중`
- `카메라 연결이 끊겼습니다`
- `라즈베리 파이와 연결이 끊겼습니다`
- `카메라 스트림 오류`

### 6.2. 카메라 상태 polling 추가

`frontend/static/script.js`에 추가한다.

```javascript
function fetchCameraStatus() {
    fetch('/api/stream_status')
        .then(response => response.json())
        .then(updateCameraStatus)
        .catch(() => showCameraDisconnected('서버와 연결이 끊겼습니다'));
}

setInterval(fetchCameraStatus, 1000);
```

### 6.3. UI 갱신 함수 추가

예상 동작:

```javascript
function updateCameraStatus(data) {
    if (data.camera_state === 'live') {
        showCameraLive();
        return;
    }

    showCameraDisconnected(data.message || '카메라 연결 상태를 확인할 수 없습니다');
}
```

`live`일 때:

- `#camera-stream` 표시
- `#no-camera-msg` 숨김
- `#video-wrapper`에서 비활성 상태 클래스를 제거
- 상단 `LIVE` 배지는 기존 강조 색상 유지

연결 끊김 또는 오류일 때:

- `#video-wrapper`에 비활성 상태 클래스를 추가해 영상 영역을 회색 톤으로 변경
- 기본 추천: 마지막 프레임은 흐리게/회색 처리하고, `#no-camera-msg`를 오버레이로 표시
- 서버 연결 자체가 끊긴 경우에는 `#camera-stream` 숨김 처리 가능
- 상단 `LIVE` 배지는 선택적으로 회색 또는 `OFFLINE` 상태로 변경

### 6.4. `handleCameraError()` 보강

현재 `handleCameraError()`는 이미지를 숨기고 메시지만 표시한다.

새 구조에서는 `img.onerror`는 보조 수단으로만 사용한다.

변경 방향:

```javascript
function handleCameraError() {
    showCameraDisconnected('영상 스트림을 불러올 수 없습니다');
}
```

### 6.5. 스타일 보강

`frontend/static/style.css`의 `.no-camera-bg`를 오버레이 메시지로 다듬는다.

권장:

- 화면 중앙 배치
- 반투명 어두운 배경
- 상태별 색상 클래스 선택 가능
- 마지막 프레임 위에서도 문구가 잘 보이도록 처리

예시 클래스:

```css
.camera-offline {
    background: #d1d5db;
}

.camera-offline #camera-stream {
    filter: grayscale(1);
    opacity: 0.25;
}

.no-camera-bg {
    position: absolute;
    inset: 0;
    align-items: center;
    justify-content: center;
    background: rgba(15, 23, 42, 0.72);
    color: #fff;
    font-weight: 700;
    z-index: 20;
}
```

상태에 따라 `#video-wrapper`에 `.camera-offline` 클래스를 붙이면, 카메라 이미지 영역 전체가 회색으로 바뀐다.

추가 선택 사항:

```css
.live-badge.offline {
    background: #9ca3af;
    color: #ffffff;
}
```

연결 끊김 상태에서 헤더의 `LIVE` 배지도 회색으로 바꾸거나, 텍스트를 `OFFLINE`으로 변경할 수 있다.

## 7. 라즈베리 파이 변경 계획

대상 파일: `raspberry/pi_client.py`

필수 변경은 아니다. 서버의 프레임/상태 타임아웃만으로도 기본 기능은 구현 가능하다.

다만 더 정확한 구분을 위해 다음 정보를 `/status`에 포함하는 개선을 고려한다.

```json
{
  "camera": "ok",
  "camera_error": null
}
```

카메라를 열 수 없는 경우:

```json
{
  "camera": "error",
  "camera_error": "camera open failed"
}
```

프레임 캡처 실패가 반복되는 경우:

```json
{
  "camera": "error",
  "camera_error": "frame capture failed"
}
```

이 값이 있으면 서버는 `robot_disconnected`와 `camera_disconnected`를 더 정확히 구분할 수 있다.

## 8. 테스트 계획

### 8.1. 정상 상태

1. 서버 실행
2. 라즈베리 파이에서 스트림 전송
3. 대시보드 접속
4. `/api/stream_status` 확인

기대 결과:

```json
{
  "camera_state": "live",
  "camera_connected": true
}
```

대시보드에는 영상이 표시되고 연결 끊김 메시지는 보이지 않는다.

### 8.2. 카메라 스트림 중단

1. 라즈베리 파이 상태 전송은 유지
2. 영상 전송만 중단
3. `CAMERA_TIMEOUT_SEC` 이후 대시보드 확인

기대 결과:

- `camera_state = camera_disconnected`
- 대시보드 `실시간 카메라` 영역에 `카메라 연결이 끊겼습니다` 표시

### 8.3. 라즈베리 파이 전체 중단

1. 라즈베리 파이 클라이언트 전체 종료
2. `ROBOT_STATUS_TIMEOUT_SEC` 이후 대시보드 확인

기대 결과:

- `camera_state = robot_disconnected`
- 대시보드 `실시간 카메라` 영역에 `라즈베리 파이와 연결이 끊겼습니다` 표시

### 8.4. 스트림 재연결

1. 중단된 스트림 재시작
2. 새 프레임이 서버에 들어오는지 확인

기대 결과:

- `camera_state = live`로 복귀
- 연결 끊김 오버레이 자동 숨김
- 영상 표시 재개

### 8.5. 서버 연결 실패

1. 대시보드 열린 상태에서 서버 종료
2. 프론트의 `/api/stream_status` 요청 실패 확인

기대 결과:

- `서버와 연결이 끊겼습니다` 메시지 표시
- 브라우저 콘솔에 치명적인 반복 오류가 과도하게 쌓이지 않음

## 10. 완료 기준

- 정상 영상 수신 시 오버레이가 보이지 않는다.
- 프레임 수신이 일정 시간 멈추면 `실시간 카메라` 영역이 회색으로 바뀌고 연결 끊김 메시지가 표시된다.
- 라즈베리 파이 전체 연결 끊김과 카메라만 끊긴 상황을 가능한 범위에서 구분한다.
- 스트림이 재연결되면 새로고침 없이 영상 표시 상태로 자동 복귀한다.
- 스트림이 재연결되면 회색 화면 상태가 해제되고 기존 영상 색상으로 돌아온다.
- 기존 `/video_feed`, `/get_status`, `/api/stream_status` 동작과 호환성을 유지한다.

## 11. 주의 사항

- 마지막 프레임을 즉시 삭제하지 않는다. 사용자는 마지막 화면 위에서 연결 끊김 메시지를 보는 편이 상황 파악에 유리하다.
- `img.onerror`는 보조 수단으로만 사용한다. 주 판단은 `/api/stream_status` polling으로 한다.
- `/api/stream_status` 기존 디버그 필드는 유지해 이전 문서와 테스트 절차가 깨지지 않게 한다.
