# 20260731 [FULL] 로그인·회원가입·이메일 인증 구현 계획

## 1. 목표

- FastAPI 통합 서버의 `/login`에서 MySQL `dabom.users` 기반 로그인과 회원가입을 제공한다.
- 프로젝트 전용 `no-reply` SMTP 계정으로 가입 이메일 인증번호를 발송한다.
- 인증된 이메일, 유효한 로그인 ID, 비밀번호, 이름, 전화번호, 사번을 검증한 뒤 사용자 계정을 저장한다.
- 삭제 처리된 계정은 로그인할 수 없고, 정상 계정의 로그인 성공 시 세션과 `login_at`을 갱신한다.

## 2. 수정·생성 대상

- `server/app.py`: 인증 라우트, 세션 보호, DB/SMTP 서비스 초기화를 연결한다.
- `server/auth_service.py`(생성): 입력 검증, 비밀번호 해싱, 회원가입, 로그인, 인증번호 상태를 담당한다.
- `server/database.py`(생성): 환경 변수 기반 MySQL 연결과 파라미터 바인딩 쿼리를 담당한다.
- `server/email_service.py`(생성): 전용 no-reply SMTP 계정의 인증 메일 발송을 담당한다.
- `frontend/templates/login.html`: 로그인·회원가입 화면과 접근성 있는 입력 폼을 구현한다.
- `frontend/services/static/login.js`: 인증/중복 확인/가입/로그인 API 호출과 버튼 상태를 담당한다.
- `frontend/services/static/style.css`: 로그인·회원가입 UI 스타일을 추가한다.
- `requirements.txt`: MySQL 및 비밀번호 해싱 패키지를 명시한다.
- `data/database/20260731_add_users_login_id_and_email_verifications.sql`(생성): 기존 `dabom` DB를 삭제하지 않고 로그인 ID와 이메일 인증 저장소를 추가한다.
- `.env.example`(생성): DB, no-reply SMTP, 세션, 인증 제한 환경 변수 예시를 제공한다.

## 3. 핵심 설계

- DB·SMTP 자격 증명은 코드에 저장하지 않고 환경 변수에서만 읽는다.
- 인증번호는 난수 원문이 아니라 해시값과 만료 시각만 DB에 저장한다.
- 인증번호 재전송 쿨다운, 발송 횟수 제한, 검증 시도 제한, 일회성 사용을 서버에서 강제한다.
- 중복 확인은 UI 보조용 API와 회원가입 트랜잭션 직전의 최종 검증을 모두 수행한다.
- 비밀번호는 bcrypt 해시로 저장·비교하고, 모든 SQL은 파라미터 바인딩을 사용한다.
- 세션 쿠키에는 `HttpOnly`, `SameSite=Lax`, HTTPS 운영 시 `Secure`를 적용한다.

## 4. DB 변경 주의

- 기존 `init_schema.sql`은 `DROP DATABASE`를 포함하므로 운영 DB에 실행하지 않는다.
- 새 마이그레이션은 `users.login_id`와 `email_verifications`만 추가한다.
- 기존 사용자의 `login_id` 백필 정책은 실제 운영 데이터 확인 후 별도로 결정한다. 신규 가입과 신규 로그인은 `login_id`를 기준으로 한다.

## 5. 검증 계획

- 이메일 인증 전 가입 입력 비활성화, 인증 성공 후 활성화를 확인한다.
- 로그인 ID/이메일/사번 중복, 잘못된 입력, 만료·재사용·오입력 인증번호를 서버 API 수준에서 검증한다.
- 가입 성공 시 `users`에 bcrypt 해시가 저장되는지 확인한다.
- 정상 로그인, 잘못된 자격 증명, 삭제 계정 차단, 로그인 성공 후 `login_at` 갱신을 확인한다.
