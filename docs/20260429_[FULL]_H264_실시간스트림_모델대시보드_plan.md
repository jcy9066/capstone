# 20260429 [FULL] H.264 실시간 스트림 모델 대시보드 계획

## 1. 작업 목표

Raspberry Pi에서 Python 코드를 실행하지 않고, `rpicam-vid`로 실시간 H.264 영상을 GPU 서버에 push한다.

GPU 서버는 수신한 H.264 스트림을 디코딩해 프레임 단위로 변환하고, 선택된 1~9번 모델 파이프라인으로 실시간 추론을 수행한 뒤 대시보드 `/video_feed`에서 결과 영상을 표시한다.

## 2. 왜 JPEG가 아닌 H.264인가

JPEG POST는 정지 이미지 수신과 대시보드 표시를 빠르게 검증하기 위한 임시 방식이다.

실제 실시간 영상은 다음 이유로 H.264가 더 적합하다.

```text
네트워크 대역폭이 낮음
Raspberry Pi 카메라 하드웨어 인코더 활용 가능
프레임 단위 JPEG 반복 POST보다 실시간 스트림에 가까움
운영 구조에서 더 자연스러움
```

단, GPU 서버의 모델은 결국 OpenCV/Numpy 프레임을 입력으로 받으므로, 서버 쪽에서는 H.264를 디코딩해 frame으로 변환해야 한다.

## 3. 최종 흐름

```text
Raspberry Pi
rpicam-vid H.264 encode
↓
HTTP POST /stream/h264
↓
GPU Server
ffmpeg decode
↓
OpenCV BGR frame
↓
FrameProcessor
↓
1~9번 pipeline 추론
↓
Dashboard /video_feed
```

## 4. Raspberry Pi 실행 예시

```bash
rpicam-vid -t 0 --codec h264 --inline --width 640 --height 480 --framerate 15 -o - | \
curl --http1.1 -v -N -X POST -T - \
  -H "Content-Type: video/H264" \
  -H "Transfer-Encoding: chunked" \
  "http://10.108.90.21:21063/stream/h264?robot_id=pi-01"
```

## 5. GPU 서버 실행 예시

파이프라인 선택:

```env
PIPELINE=1
```

서버 실행:

```bash
cd ~/capstone
uvicorn server.app:app --host 0.0.0.0 --port 21063
```

## 6. 구현 대상

```text
server/app.py
README.md
```

`server/app.py`에는 다음을 추가한다.

```text
POST /stream/h264
ffmpeg subprocess 디코딩
디코딩된 raw BGR frame을 기존 frame 처리 함수로 전달
대시보드 latest frame 갱신
```

## 7. 필요 패키지

GPU 서버에 `ffmpeg` 실행 파일이 필요하다.

```bash
ffmpeg -version
```

없으면 conda 또는 apt로 설치한다.
