# 구조 분리 작업 계획서

## 작업 범위

- 범위 태그: `[FULL]`
- 작업명: 구조_분리
- 목적: 관제 센터 대시보드 코드, 라즈베리파이 영상 수신 및 실시간 pose estimation 코드, 향후 SLAM/자율주행 코드를 서로 다른 디렉토리로 분리한다.

## 요구사항 분석

- 대시보드 관련 파일은 모두 `capstone/frontend` 아래로 이동한다.
- 라즈베리파이에서 영상을 받아 실시간 pose estimation을 수행하는 코드 부분은 적절한 이름의 디렉토리로 이동한다.
- 향후 SLAM 기반 자율주행이 들어갈 디렉토리를 적절한 이름으로 생성한다.
- 이번 작업은 파일 내용 수정이 아니라 파일 위치 조정이 핵심이다.

## 이동 계획

- `frontend/`
  - `app.py`
  - `templates/`
  - `static/`
- `perception/`
  - `main.py`
  - `local_cam.py`
  - `core/`
  - `models/`
  - `stream/`
  - `utils/`
  - `config/`
- `navigation/`
  - 향후 SLAM 및 자율주행 코드를 위한 디렉토리
  - 현재는 빈 디렉토리를 git에 남길 수 있도록 `.gitkeep`을 둔다.

## 제외 대상

- `PROJECT.md`, `AGENT.md`, `README.md`, `.gitignore`, `.env`는 프로젝트 루트에 유지한다.
- `data/`, `weights/`, `output/`은 대용량 입력/가중치/결과 산출물 성격이 강하므로 이번 구조 분리에서는 위치를 바꾸지 않는다.
- `.git/`, `__pycache__/`는 직접 수정하지 않는다.

## 검증 계획

- 파일 이동 후 `find`로 새 디렉토리 구조를 확인한다.
- `git status --short`로 이동/생성 상태를 확인한다.
- 코드 내용 수정은 하지 않으므로 실행 테스트는 수행하지 않는다.
