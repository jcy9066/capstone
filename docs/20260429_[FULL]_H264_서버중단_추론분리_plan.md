# 20260429 [FULL] H.264 스트림 서버 중단 추론 분리 계획

## 1. 문제

Raspberry Pi에서 H.264 stream push 명령은 계속 실행 중이나, 대시보드 브라우저에서 다음 오류가 발생했다.

```text
GET /get_status net::ERR_CONNECTION_REFUSED
video_feed net::ERR_INCOMPLETE_CHUNKED_ENCODING
```

이는 대시보드 JS 문제가 아니라, GPU 서버의 `21063` 포트에서 통합 서버 프로세스가 중간에 죽었거나 listen을 멈춘 상태를 의미한다.

## 2. 가능 원인

```text
1. H.264 디코딩은 시작됐지만 모델 추론 과정에서 서버 프로세스가 죽음
2. 모델이 너무 무겁거나 CUDA/OOM 문제 발생
3. ffmpeg 디코딩 스레드와 모델 처리 스레드 사이에서 예외 발생
4. stream 처리 루프가 너무 빠르게 모델을 호출해 서버가 버티지 못함
```

## 3. 수정 방향

H.264 수신과 모델 추론을 분리해서 검증할 수 있게 한다.

추가 설정:

```env
INFERENCE_ENABLED=true
STREAM_INFER_EVERY_N=1
```

추가 동작:

```text
/stream/h264?infer=false
  -> 모델 추론 없이 H.264 디코딩 결과만 대시보드에 표시

/stream/h264?infer=true
  -> 모델 추론 수행

STREAM_INFER_EVERY_N
  -> N프레임마다 한 번만 모델 추론하고 나머지는 raw frame publish
```

## 4. 검증 순서

1. raw stream만 확인

```bash
rpicam-vid ... | curl ... "http://10.108.90.21:21063/stream/h264?robot_id=pi-01&infer=false"
```

2. 대시보드에 원본 영상이 보이면 H.264 경로는 정상이다.
3. 그 다음 `infer=true`로 모델 추론을 켠다.
4. 서버가 죽으면 모델/CUDA/OOM 쪽 문제로 확정한다.
