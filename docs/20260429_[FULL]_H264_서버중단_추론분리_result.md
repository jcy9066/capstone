# 20260429 [FULL] H.264 스트림 서버 중단 추론 분리 결과

## 1. 작업 요약

H.264 stream 입력 시 서버가 중단되는지, 모델 추론 때문에 중단되는지 구분할 수 있도록 `/stream/h264`에 추론 on/off 옵션을 추가했다.

## 2. 수정 파일

```text
server/app.py
.env
README.md
```

## 3. 추가 설정

```env
INFERENCE_ENABLED=true
STREAM_INFER_EVERY_N=1
```

## 4. 추가 동작

원본 스트림만 확인:

```text
POST /stream/h264?robot_id=pi-01&infer=false
```

모델 추론 포함:

```text
POST /stream/h264?robot_id=pi-01&infer=true
```

`STREAM_INFER_EVERY_N` 값이 3이면 3프레임마다 한 번만 모델 추론을 수행한다.

## 5. 검증

수행:

```bash
python -m py_compile server/app.py
```

## 6. 다음 테스트 순서

1. GPU 서버 재시작

```bash
uvicorn server.app:app --host 0.0.0.0 --port 21063
```

2. Raspberry Pi에서 원본 stream만 전송

```bash
rpicam-vid -t 0 --nopreview --codec h264 --inline --width 640 --height 480 --framerate 15 -o - | \
curl --http1.1 -v -N -X POST -T - \
  -H "Content-Type: video/H264" \
  -H "Transfer-Encoding: chunked" \
  "http://10.108.90.21:21063/stream/h264?robot_id=pi-01&infer=false"
```

3. 대시보드에 원본 영상이 보이면 추론을 켠다.

```bash
rpicam-vid -t 0 --nopreview --codec h264 --inline --width 640 --height 480 --framerate 15 -o - | \
curl --http1.1 -v -N -X POST -T - \
  -H "Content-Type: video/H264" \
  -H "Transfer-Encoding: chunked" \
  "http://10.108.90.21:21063/stream/h264?robot_id=pi-01&infer=true"
```

4. `infer=false`는 정상이고 `infer=true`에서 서버가 죽으면 모델/CUDA/OOM 문제로 본다.
